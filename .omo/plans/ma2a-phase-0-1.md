# ma2a-phase-0-1 - Work Plan

## TL;DR (For humans)
**What you'll get:** A secure cross-platform MA2A foundation with one persistent identity, private multi-Space membership/discovery, contiguous enrollment validation, and bounded active-dial synchronization of signed Space control state, plus direct/private/public-relay connectivity, a minimal encrypted Echo test, and one binary containing the daemon, CLI, embedded relay, and authenticated local Web console.

**Why this approach:** Trust, synchronization, and visibility stay Space-scoped while normal operations remain Endpoint-centric, preventing metadata leakage and cross-Space privilege composition. Enrollment and control updates preserve the contiguous signed membership chain, Endpoint-owned objects are bound to their actual signer, and Iroh remains responsible for transport and effective path/home selection.

**What it will NOT do:** It will not add a global registry, general files/shell/agent/plugin services, CRDT/generic pub-sub, public remote administration, installers/self-update, or a custom NAT/routing/home-selection system. It will not promise full relay-backed cold starts when a multi-Space Endpoint has no common compatible relay.

**Effort:** XL
**Risk:** High - cryptographic state propagation, private discovery, Iroh relay-map/home behavior, native relay TLS, cross-platform IPC, and x86_64/ARM64 releases all require adversarial integration proof.
**Decisions to sanity-check:** Identity keys use platform protection with a strict current-user-file fallback; enrollment transfers every required manifest generation because Phase 1 has no checkpoint; control sync may actively dial a bounded peer subset without maintaining a mesh; embedded Private Relays may use native operator-supplied TLS or optional external termination.

## Scope
### Must have
- One Rust 2024 workspace producing one end-user binary named `ma2a`, with strict lint/type/error rules and source files kept below 250 pure LOC.
- Locked Universe/Space/Endpoint ontology: no global Universe registry; one persistent Endpoint per Runtime; Endpoint membership is `0..N` Spaces and is stored separately from Endpoint identity.
- SQLite state from schema version 1, crash-safe migrations/transactions, protected-key references only, persistent Endpoint identity, and a separate Space authority signing key.
- Owner-signed deterministic-CBOR Space genesis/membership/revocation state with monotonic generation, previous-hash binding, highest-observed rollback protection, partition-tolerant cached membership, and no mandatory membership lease.
- Short-lived single-use owner-approved enrollment over a bootstrap-only protocol; zero-Space Endpoints deny normal metadata, discovery, relay advertisements, and Echo access.
- Endpoint-centric authorization: normal operations target an Endpoint, derive shared Spaces internally, accept one complete independent Space allow, never combine partial privileges, and keep `authorized_via` internal.
- Explicit Iroh composition using `iroh 1.1.0`: persistent Endpoint, MA2A private target-specific `AddressLookup`, Endpoint-hosted MA2A Private Relay role, separate Public Iroh Relay fallback, and no unchanged `presets::N0`/public DNS-Pkarr publication.
- Target-specific signed `SpaceAddressRecord` validation, actual EndpointData publication, separate Private Relay eligibility/home-relay compatibility, current-Iroh single-home constraints, degraded reachability reporting, and source-driven scenarios A-F.
- Narrow authenticated `ma2a/control/1` synchronization between existing members for bounded active dialing/pull plus opportunistic push of newer signed Space manifests, current/fresh target address records, and current/fresh Private Relay advertisements; a pre-existing connection is not required, and forwarding remains unchanged with original-signature/signer-identity validation.
- Minimal bounded encrypted Echo/Test request-response seam only.
- Current-user daemon auto-start and exact-version local IPC: Unix-domain sockets on Linux/macOS and ACL-restricted, remote-rejecting named pipes/equivalent on Windows.
- Loopback-only Axum API, CLI-only password initialization/reset, Argon2id verifier, revocable server-side sessions, Host/Origin/CSRF protections, authoritative snapshots, and best-effort SSE with revision-gap resnapshot.
- React + Vite + TypeScript + Tailwind UI embedded into the release binary; Linux/macOS/Windows x86_64 and ARM64 archives wherever the pinned stack supports them, with unsupported combinations explicitly evidenced/documented, plus checksums, SBOM, provenance, and clean-artifact smoke tests.

### Must NOT have (guardrails, anti-slop, scope boundaries)
- No `UniverseId`, global registry, mandatory Space membership, Space-addressed normal commands, cross-Space privilege composition, global-deny semantics, or Endpoint identity containing a Space ID.
- No Member/Device/Human/Account identity hierarchy, shared-Space-secret authority, multi-admin consensus, MLS, content-key rotation, reusable/fleet invites, cross-Space grants, or automatic key replication/recovery product.
- No unchanged N0 preset, public MA2A address publication, generic `SpaceRelaySet`, synthesized target relay addresses, assumption that all eligible relays are persistent homes, or correctness dependence on opportunistic Iroh route reuse.
- No separate Relay identity/membership/authority/feed, MA2A NAT traversal/routing/scoring, automatic Relay Provider promotion, or automatic DNS/TLS provisioning.
- No Files, Exec, Shell, Process, Agent, A2A, Proxy, RCAN, dynamic plugins, service reflection, generic schema/artifact framework, or third-party Service SDK.
- No public/remote Web UI, browser-side password setup, URL credentials, OAuth/WebAuthn/2FA/multi-user auth, durable UI event log, exact event replay, or exactly-once UI semantics.
- No CRDT, consensus, durable Space event log, exact Space-control replay, generic pub/sub, mandatory `iroh-gossip`, or globally replicated Space database for control-state synchronization.
- No native installers, package-manager publishing, native login services, self-update, source-tree runtime assets, or runtime frontend network fetches.

## Commit strategy
- Use one reviewable Conventional Commit per Todo in the order shown; a Todo's implementation and tests land together. Documentation that defines the same contract stays in that Todo's commit.
- Before every commit run the narrow package/frontend tests for that Todo; before Wave completion run workspace/frontend quality gates; before release run all gates plus E2E and clean-archive smoke.
- Do not squash away security/protocol migration history during execution, do not amend already-reviewed commits without surfacing it, and never use destructive cleanup/force push. Generated release artifacts/evidence are not committed unless the repository policy explicitly requires them.
- If a Todo uncovers an Iroh 1.1 API mismatch, first add a failing source-driven test and update the plan/evidence with the minimal adapter/rebuild correction; do not redesign MA2A transport semantics or silently upgrade Iroh.
