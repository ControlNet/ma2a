## 本轮发现

### F01 · 高 · 升级后仍可能误删旧上传登记指向的文件

**位置与证据（静态，三平台）。** 在 `c4f72a2`，`crates/ma2a-services/src/transfer/upload.rs:72–86` 先记旧式文件名，再独占创建；若名称已被占用便保留记录。当前文件第 34–41、88–97 行修正新请求。`crates/ma2a-runtime/src/lifecycle.rs:87–88` 启动时仍调用 `store/services.rs:103–109,162–172`，接受旧长度的十六进制名称，按路径直接删除。该范围没有更改迁移或清扫器。

**触发与影响。** 旧版曾因同名既有文件而拒绝上传，并留下了日志行。正常升级后的第一次启动就会清扫它，可能删除从未属于该上传的文件。无需新上传或异常关机。

**修复与验收。** 区分历史格式与新格式。对历史行缺乏归属证据时保留文件，单独处理日志。用旧版数据库状态验收升级，逐字节比较原文件，并确认新格式的真实暂存物仍能回收。

### F02 · 高 · 远端 Agent 制品可通过传输校验却与发布记录不符

**位置与证据（静态，三平台）。** `crates/ma2a-runtime/src/agents/artifacts.rs:178–196` 用记录的 BLAKE3 找文件，再交给通用 Transfer。`crates/ma2a-services/src/transfer/download.rs:106–117,151` 用此次读到的内容生成成功摘要。远端 CLI 在 `crates/ma2a-app/src/commands/remote/agent.rs:233–245` 即可发布。A2A 在 `crates/ma2a-app/src/a2a/artifact.rs:48–85` 已有任务元数据，`a2a/remote.rs:185–195` 却只验证传输自身。A2A 的本地分支在 `a2a/artifact.rs:136–143` 确实对照了原记录。

**触发与影响。** 已入库的 blob 发生等长存储损坏时，两端对损坏字节算出的传输摘要一致。远端 CLI 可保存错误制品，A2A 可完整返回与任务卡所示 BLAKE3 不同的内容。

**修复与验收。** 服务端在发成功终帧前比对持久化的制品大小和摘要；已持有预期值的消费者也应核对。以完整、等长损坏、截短三种存储夹具验收，只有完整内容可按成功发布，HTTP 错误内容不得正常结束。

### F03 · 高 · 正常包的 WOFF2 响应使发布冒烟失败

**位置与证据（Linux 实测，另两平台静态）。** `web/src/styles/fonts.css:8,20` 引入随包字体，`crates/ma2a-runtime/src/web/assets.rs:38` 返回 `font/woff2`。`scripts/smoke-release.sh:110–119` 对未列出的扩展名期待 `application/octet-stream`。用真实前端和本机 debug 二进制制成符合布局的 Linux 归档，实际冒烟在首个字体处退出 1。日志为 `release-metadata.log`。

**触发与影响。** 默认构建已经包含字体。`.github/workflows/release.yml:94–100` 对三个受支持的 x86_64 目标运行相同门禁，正常包无法进入后续发布阶段。

**修复与验收。** 给 WOFF2 设定明确期望，并让真实归档走完整冒烟。三个原生目标的正常包应通过；故意缺字体或返回错误类型的测试包仍应失败。

### F04 · 高 · 标签发布作业无法确定目标仓库

**位置与证据（工作流静态，本地只读验证）。** `.github/workflows/release.yml:165–186` 在独立 runner 只下载资产，未 checkout；没有设置 `GH_REPO`，调用 `gh release create` 时也没有传 `--repo`。在无 Git 工作树的同等目录布局，保留 Actions 的仓库环境变量，运行只读 `gh release view --json name`；退出 1，提示当前目录不是 Git 仓库。

**触发与影响。** 标签构建完成、资产已经下载时，最终作业仍缺少仓库上下文。此问题独立于 F03。本轮没有创建或发布 Release。

**修复与验收。** 将工作流自带的仓库全名显式交给 gh。先在无 checkout 的作业用只读命令验证实际目标，再在项目既有预发布流程中验收资产清单。

### F05 · 高 · Windows 多级目录的私有创建未覆盖直接 Store 入口及并发创建

**位置与证据（静态，Windows）。** `crates/ma2a-runtime/src/ipc/windows.rs:46–61` 逐级创建缺失目录；中间级返回 AlreadyExists 时只改变布尔值，继续创建下一层，最后只处理叶子。`crates/ma2a-store/src/repository.rs:26–27` 经 `key_store.rs:164` 进入 `permissions.rs:5–10,96–99`，Windows 仍普通递归创建后才设叶子 ACL。直接库调用没有 CLI 守护进程的 IPC 预处理。

**触发与影响。** 状态路径有多层尚不存在，且上级允许其他账户修改子项时，直接 Store 创建的中间层可能继承过宽权限；IPC 创建期间并发出现的中间层也没有得到承诺的验证。后续仅检查叶子不能证明路径各级可安全使用。未观察到实际凭据泄露。

**修复与验收。** 把带受保护描述符的逐级创建下沉至共同入口；发生同名竞争时验证该级，失败就停止。用原生 Windows 对直接 Store、Runtime 和 IPC 的多级冷启动分别检查所有新增级的 ACL，并覆盖并发创建。

### F06 · 高 · 撤权后阻塞任务仍可创建目录或替换目标文件

**位置与证据（静态，三平台）。** `crates/ma2a-services/src/files.rs:66–79,171` 将停止标志传给删除，分级 mkdir 和写提交没有使用它。`files/ops.rs:110–118` 逐级创建；`transfer/upload.rs:135–139` 也把发布交给阻塞任务。`files/commit.rs:56–65` 先同步数据，再改名或建立最终链接。外层 `crates/ma2a-runtime/src/stream_host/inbound.rs:159–188` 可以先因撤权结束等待。

**触发与影响。** 在两级 mkdir 之间撤权，后续目录仍可创建。在最终文件尚未发布、同步仍在进行时撤权，先前排队的工作仍可在同步结束后替换原文件。影响超出已经进入的单次文件系统调用。

**修复与验收。** 把取消状态传至分级创建和发布，在每次修改及同步完成、进入原子发布前检查。用可控同步点分别暂停在两个位置，撤权后应保留原目标、不再新增下级目录，并归还暂存资源。

### F07 · 中 · 工作区下载核对目录前已能清除旧进度

**位置与证据（静态，三平台）。** `crates/ma2a-runtime/src/agents/tools/files.rs:141–160` 先 `Partial::open(..., false)`，随后检查所持目录是否仍等于工作区目的地。`crates/ma2a-services/src/client/resume.rs:81–102` 在 open 中就可截断已识别的 partial 并删除它的 sidecar。错误分支还会 discard。

**触发与影响。** 同账户的另一个作业在初次检查与目录打开之间轮换目录，实际打开的位置恰有同目标的可续传进度。工具即使最终拒绝发布，也已破坏那份进度。这里的副作用发生在身份复核之前，属于工具的路径正确性。

**修复与验收。** 先取得并验证父目录句柄，随后用这个句柄打开或创建辅助文件。并发轮换测试除核对最终文件外，也应逐字节比较另一目录原有的 partial 与 sidecar。

### F08 · 中 · 注销最终返回 403 时，界面仍显示已退出

**位置与证据（静态调用链，Web 单元测试实测）。** `web/src/api/web-auth.ts:61–83` 对已轮换的 Cookie 重试一次，最终 403 会抛出错误；`web/src/api/web-auth.test.ts:74–85` 也验证了拒绝分支。其调用方 `web/src/app.tsx:111–126` 吞掉 401 和 403，停止控制器、清空页面会话并导航到登录页。`crates/ma2a-runtime/src/web.rs:94–109,135–154` 可以在撤销前返回 403，只有注销成功才令 Cookie 过期。

**触发与影响。** 多个标签页先后登录，若当前 Cookie 在注销重试前再次变动，两次请求都可因 CSRF 不匹配被拒。页面显示已退出，当前浏览器会话仍可用于刷新后的访问。现有单测只保证 helper 抛错。

**修复与验收。** 仅在确认会话已失效或注销成功后清空界面；最终 403 应保留会话并告知注销未完成。用多标签页覆盖一次轮换成功及最终拒绝，分别检查路由、刷新结果和服务端会话记录。

### F09 · 中 · Web 读取会话的存储错误被当成凭据失效

**位置与证据（静态，三平台）。** `crates/ma2a-runtime/src/web/types.rs:84–87` 把 Store 错误映射为 Internal，`web/auth.rs:215–230` 读写会话时传播它。但 `web/runtime_routes.rs:31–37,119–122` 和 `web/runtime_routes/events.rs:51–56` 对所有错误一律返回 401。前端 `web/src/runtime-controller.ts:254–259` 因 401 停止控制器，`web/src/app.tsx:86–90` 随即清空会话，切到登录页。

**触发与影响。** 有效会话读取快照时遇到 SQLite I/O 错误，用户会被导向登录页，即使底层很快恢复。上轮对注销请求中内部错误的修补未覆盖这些只读入口。

**修复与验收。** 共用明确区分鉴权拒绝与内部故障的状态码映射。对存在的会话让仓库返回一次内部错误，检查快照、分页读和事件入口均返回服务错误；恢复后页面能继续使用已有会话。过期会话仍应要求重新登录。

### F10 · 中 · Proxy、Agent 和服务描述仍有无界的首帧或响应写入

**位置与证据（静态，三平台）。** `crates/ma2a-services/src/proxy.rs:35–49` 连上 TCP 后直接等待写 accept，随后才进入可取消的转发。`crates/ma2a-runtime/src/stream_host/inbound.rs:196–209,228–239` 直接等待 Proxy 或 Describe 响应。`crates/ma2a-runtime/src/agents/watch.rs:48–56`、`agents/host.rs:174–184` 也直接等待 accept。公共 helper 在 `crates/ma2a-services/src/reply.rs:22–36` 已有取消与宽限处理。

**触发与影响。** 对端仍连接、输出受流控且不能写完这一帧时，这些路径不能在承诺的宽限内退出。Proxy 在此期间还持有已建立的本地 TCP 连接。Linux 对正常转发及进入循环后的取消测试通过。

**修复与验收。** 让这些入口共用有界帧写入，覆盖拒绝、首帧、终帧和关闭。用在指定阶段暂停的内存 writer 验收撤权和超时，并确认连接、并发许可和作业都得到释放。

### F11 · 中 · 可预判的邀请输出失败仍消耗 revision，Unix 写错还会占住最终名

**位置与证据（Linux 既有测试及静态）。** `crates/ma2a-runtime/src/ipc/server/execute/invite_file.rs:7–12` 只查路径语法，`execute/space.rs:44–62` 先提交邀请再交付文件。`ipc/server_tests/failed_replay.rs:12–17,56–62` 用已有目录作输出，实际通过的测试确认请求报告失败而库中已有一条邀请，重放不会再签发。Unix 分支在 `invite_file.rs:19–27` 直接创建最终文件，写失败即返回；Windows 分支在第 57–74 行先写暂存文件再发布。

**触发与影响。** 已有同名文件或目的地父目录缺失时，三个平台均可能产生无法交付的邀请并推进 revision。Linux/macOS 若遇配额耗尽等写失败，最终名还可能留下空文件或半份票据，下一次无覆盖创建会被挡住。写错分支为静态判断。

**修复与验收。** 签发前检查并固定真实父目录，提前拒绝已占用目的地；Unix 也先写完整私有暂存文件，再无覆盖发布。覆盖单文件名、既有文件、缺失父级及提交后真正的 I/O 故障。前置拒绝应保持 revision 与原文件；后置故障应保留幂等记录且不留下半份最终票据。

### F12 · 中 · Unix 制品文件名尚未持久化就提交成功记录

**位置与证据（静态，Linux/macOS）。** `crates/ma2a-runtime/src/agents/artifacts.rs:83,97–107` 同步临时文件，再将其改名到 blob 目录；第 138–147 行随后提交制品引用及工具成功答复。两步之间没有同步包含新文件名的目录。`crates/ma2a-runtime/src/agents/artifact_read.rs:35–46` 将已引用文件缺失报为内部错误。仓库的 KeyStore 在 `crates/ma2a-store/src/key_store.rs:209–211,279–283` 有同步父目录的现成做法。

**触发与影响。** 在目录项写回前突然断电，文件系统恢复可能保住已提交的 SQLite 引用和成功答复，却丢失最终文件名。之后读取已发布制品会失败。本轮没有做掉电实验。

**修复与验收。** 将 blob 目录项及新建父目录的持久化放在成功落库前，传播目录同步失败。注入同步错误时不应留下成功记录；具备故障恢复环境时验证重启后每个已提交引用均可读取。

### F13 · 中 · 上传客户端可在发送任何内容前报告成功

**位置与证据（静态，三平台）。** `crates/ma2a-services/src/client/transfer.rs:100–105` 遇到首帧 Finished 就返回解码出的结果；未读取本地源，也未发送 commit。正常路径在第 141–145 行核对摘要和 size，漏掉 bytes。`crates/ma2a-core/src/service/transfer.rs:282–290` 解码字段，不核对相互关系。`docs/protocol/services-v1.md:161–171` 规定上传成功前要 accept、传入完整内容、提交。

**触发与影响。** 对端实现错误，提前发送成功终帧或返回矛盾的已传字节数，调用者仍可得到成功。普通的完整上传和短源测试均通过，未覆盖这种状态机差异。

**修复与验收。** 保留首帧明确失败结果；仅在收到 Put accept 并完成本地提交、字节数、大小和摘要全部吻合时报告成功。用协议单元测试覆盖提前成功、终帧计数不一致、合法拒绝和完整上传。

### F14 · 中 · A2A 在检查返回历史条数之前已经投递或取消任务

**位置与证据（静态，三平台）。** `crates/ma2a-app/src/a2a/methods.rs:84–105,141–157` 先调用 send/submit，随后才解析 `configuration.historyLength`；第 179–189 行的 CancelTask 也在取消后调用 detail。`a2a/rpc.rs:207–214` 会对无效条数返回参数错误。

**触发与影响。** 消息和任务标识有效，历史条数无效时，请求可能已经执行，调用方只看到参数错误；对取消请求也可能实际取消了任务。调用方若用新消息标识纠错重试，就可能重复执行业务操作。

**修复与验收。** 在第一次产生副作用之前完成该方法接受的所有参数校验。错误参数应使任务数、已有任务状态和事件序号保持不变；有效请求须保留原有幂等行为。

### F15 · 中 · A2A 远端取消任务的 30 秒预算起算太晚

**位置与证据（静态，三平台）。** `docs/protocol/a2a-adapter.md:81` 约定最多等待 30 秒后返回当时状态。`crates/ma2a-app/src/a2a/methods.rs:179–189` 先等待 backend.cancel 返回才启动限时器。远端分支 `a2a/remote.rs:115–119` 等待 Agent 的响应；`crates/ma2a-runtime/src/agents/host.rs:79–85` 所调的 `agents/tasks.rs:126–133` 可等终态长达 60 秒，再返回 OutcomeUnknown。

**触发与影响。** 正常维护循环会处理取消宽限；远端维护延迟或回复迟迟未到时，调用方在 30 秒后仍可能没有结果，并最终得到错误而非任务当时的状态。

**修复与验收。** 从请求取消时起共享同一截止时间，将发起取消与等待终态分开。用虚拟时钟验证立即确认、迟到确认与远端暂时不答，并检查写入的取消请求在对外超时后仍有明确状态。

### F16 · 中 · A2A 列表不检查远端分页是否前进

**位置与证据（静态，三平台）。** `crates/ma2a-app/src/a2a/list.rs:47–56,83–85` 先读取并累积所有页，再筛选调用方请求的那一页；`a2a/remote.rs:99–110` 原样转交远端 next，`crates/ma2a-core/src/service/agent_reply.rs:159–169` 只解码其类型。卡片查询在 `a2a/remote.rs:122–134` 也只看 next 是否存在。

**触发与影响。** 遇到重复非空页和游标的远端分页实现时，即使只请求一条任务，调用仍不能结束，同一组项目被反复加入内存；卡片查询也可能一直等不到结果。

**修复与验收。** 按协议的任务或 Agent ID 顺序验证分页推进；在分页中累加所需计数并只保留返回窗口。用重复游标、倒退游标、正常多页和空末页的内存接口验收，异常时应在有限次数内结束。

### F17 · 中 · Agent SDK 向受阻输出无限排队

**位置与证据（静态，三平台）。** `crates/ma2a-agent/src/sdk.rs:54–72,101–107` 把每条已编码消息送入无界队列；`sdk/task.rs:72–81` 的 progress 同步入队，没有背压。唯一写者在 `sdk.rs:265–286` 逐条等待 write_all 和 flush。单条进度有 1 KiB 上限，队列总量没有上限。

**触发与影响。** 一个持续汇报进度的正常任务遇到慢管道或暂停读取的 Runtime，积压量随时间增长，并延迟其他任务的确认与终态。输入保持打开时，连接结束阶段的排空超时不会生效。

**修复与验收。** 对队列设容量，合并可丢弃的同任务进度，为 ack、终态、工具结果保留有界的可靠传递方式。用慢速内存 writer 验证内存队列有界、恢复读取后能收到终态且顺序符合协议。

### F18 · 中 · 发布的许可证清单包含构建机的工作目录

**位置与证据（Linux 实测，跨平台脚本）。** `scripts/generate-license-report.sh:13–18` 原样合并 Rust 和前端许可证工具的 JSON；`.github/workflows/release.yml:157–161,180–186` 将该文件作为资产上传并发布。对本机的真实清单只记录计数，发现 9 个 Rust 对象键、7 个前端 paths 项包含完整检出目录。见 `release-license-paths.log`。

**触发与影响。** 在开发机或自托管 runner 生成制品时，公开附件可包含账号名或内部目录结构；仅更换构建目录也会改变清单。报告和探针日志没有列出所匹配的路径。

**修复与验收。** 规范化工作区包来源，使用包名、版本和仓库相对路径，移除机器安装路径。用两个不同根目录对同一输入生成许可证清单，确认包及许可证完整、两份都没有检出根或主目录。

### F19 · 中 · Windows 备份发布和清理只比较文件类型

**位置与证据（静态，Windows 的 Store 库接口）。** `crates/ma2a-store/src/backup.rs:26–38,109–125,137–150` 在发布及清理前调用 holds。Unix 比较设备号与 inode；Windows 只验证已持有句柄与当前名称都指向普通文件。`docs/storage.md:94–111` 说明 Windows 祖先 ACL 由操作者管理，同时承诺清理仅针对原暂存物。仓库在 `crates/ma2a-services/src/windows_files.rs:39–70` 已有文件身份查询。

**触发与影响。** 同账户的维护作业若在备份期间轮换目录别名或替换暂存条目，检查可以把另一普通文件当成刚通过 integrity_check 的备份并报告成功，清理也可能删除替代文件。影响是并发情况下的备份正确性；受信目录、没有并发轮换的日常备份不涉及该条件。

**修复与验收。** 固定实际父目录，发布和清理均校验所持文件的卷及文件 ID。原生 Windows 验收同名但不同 ID、父目录别名变化和普通成功备份，替代文件应保持原内容。

### F20 · 低 · Files 列表忽略父路径已用尽的协议预算

**位置与证据（静态，三平台）。** `crates/ma2a-services/src/files/ops.rs:62–69,89–93` 仅验证单个文件名。`crates/ma2a-core/src/service/names.rs:9–14,70–78` 同时限制全路径最多 64 个组件、组件合计最多 4096 字节。

**触发与影响。** 一个正好 64 层且能被列出的目录仍会返回正常子名；客户端把子名追加到父路径时连请求都构造不了。总长度已接近上限时也一样。

**修复与验收。** 在候选项进入分页堆之前，按父路径的剩余额度验证完整子路径。覆盖 63/64 层与字节数恰好等于、超过上限的边界，逐个检查所有返回项可以构造后续请求。

### F21 · 低 · 冒烟脚本漏查 JS 模板插值中的静态资源

**位置与证据（实测，发布脚本）。** `scripts/extract-runtime-references.pl:115–119,170–190` 跳过模板插值后把整个模板作为字符串。通过语法检查的 `release-template.mjs` 同时有普通资源引用和插值表达式内的资源引用；实际输出只含前者。真实前端本轮遇到的发布阻断另见 F03。

**触发与影响。** 前端在模板表达式内引用同源资源时，冒烟不会请求该文件；文件遗漏可一直到实际展示对应内容时才暴露。

**修复与验收。** 区分模板中的纯文本与可执行表达式，对表达式复用 JS 引用解析。现有夹具应返回两个引用，纯文本中的示例名称仍应被忽略。

### F22 · 低 · LOC 扫描会把原始字符串内容误认作块注释

**位置与证据（实测，仓库工具）。** `xtask/src/loc.rs:103,118–135` 按普通引号结束字符串，再识别块注释。对含内引号和注释标记的合法 Rust 原始字符串，`rustc` 编译夹具成功，生产计数逻辑却只计 2 行，预期 4 行。见 `release-rawstr-count.log`。

**触发与影响。** 合法源码采用这种原始字符串时，后续代码可能被算进未闭合的注释，文件 LOC 被低估，接近上限时门禁给出错误结果。

**修复与验收。** 识别 Rust 原始字符串的起止分隔符并跨行保存状态。该夹具应计 4 行，同时保留上轮行尾块注释夹具的 3 行结果。
